RPC 调用示例

一、原生币方法
eth_getBalance eth_getTransactionCount eth_gasPrice eth_chainId eth_estimateGas eth_sendRawTransaction eth_getTransactionReceipt
二、代币方法（ERC20）
balanceOf 余额 decimals 精度 symbol 名称 allowance 授权额度 approve 授权（写） transfer 转账（写）
三、合约调用方法
Factory.getPair Pair.getReserves Router.getAmountsOut Aave.getUserAccountData Aave.supply 存入（写） Router.swapExactETHForTokens（写） Router.addLiquidityETH（写）
四、读写参数对比
写交易：原生币 / ERC20 / 合约 读调用：原生币 / ERC20 / 合约

注意：JSON 本身不支持注释，本文中的 // 说明 只用于讲解。实际请求必须去掉所有 // 后面的内容。金额一律最小单位整数（ETH 18 位 / USDT 6 位 / Aave USD 价 8 位），RPC 里全部 0x 前缀 16 进制。

一、原生币方法

原生币（ETH/BNB）的余额、nonce、gas 等由节点直接提供，不经过任何合约。每个 RPC 的固定外壳（jsonrpc / id / method）都是同一套，下面每个示例仍逐字段标注。

eth_getBalance — 查原生币余额

// 请求
{
  "jsonrpc": "2.0",              // 协议版本，固定 2.0
  "id": 1,                       // 请求序号，响应原样带回，用于配对响应和请求
  "method": "eth_getBalance",    // 方法名：查地址的原生币余额
  "params": [                    // 固定 2 个参数：
    "0x1492bb948655f48d970B0459ADdb6D965545fD60",  // 参数1 = 要查的钱包地址
    "latest"                     // 参数2 = 执行区块："latest" 最新已确认 / "pending" 含未打包 / "0x64a3b" 指定块号
  ]
}
// 响应
{
  "jsonrpc": "2.0",              // 与请求相同
  "id": 1,                       // 与请求 id 相同 → 配对
  "result": "0x1bc16d674ec80000" // 余额（wei，hex）：转 10 进制 = 2000000000000000000 ÷ 10^18 = 2 ETH
}

eth_getTransactionCount — 查 nonce（账号已发交易数）

{
  "jsonrpc": "2.0",              // 协议版本
  "id": 2,                       // 请求序号
  "method": "eth_getTransactionCount",  // 查账号已发交易数（= 下一笔交易的 nonce）
  "params": [                    // 固定 2 个参数：
    "0x1492bb948655f48d970B0459ADdb6D965545fD60",  // 参数1 = 发起交易的地址
    "pending"                    // 参数2 = 计数范围："pending" 把 mempool 未打包交易也算上（防 nonce 撞车）；"latest" 只算已上链
  ]
}
// 响应 result: "0x7"  —— hex 转 10 进制 = 7；下一笔交易的 nonce 填 7

eth_gasPrice — 查当前 gas 单价

{
  "jsonrpc": "2.0",              // 协议版本
  "id": 3,                       // 请求序号
  "method": "eth_gasPrice",      // 查网络当前建议的 gas 单价
  "params": []                   // 无参数（信息全在网络侧，不需要输入）
}
// 响应 result: "0x9502f900"  —— hex 转 10 进制 = 2500000000 wei = 2.5 gwei
// 转账成本估算：21000 gas × 2.5 gwei = 52500000000000 wei ≈ 0.0000525 ETH

eth_chainId — 查网络 ID（防重放）

{
  "jsonrpc": "2.0",              // 协议版本
  "id": 4,                       // 请求序号
  "method": "eth_chainId",       // 查当前连接的是哪个网络
  "params": []                   // 无参数
}
// 响应 result: "0xaa36a7"  —— hex 转 10 进制 = 11155111 = Sepolia
// 常见值：主网 1（0x1）、BSC 56（0x38）、Sepolia 11155111（0xaa36a7）
// 作用：签名时 chainId 烧进签名里，别的网络上这笔交易无法重放

eth_estimateGas — 预估 gas 上限

{
  "jsonrpc": "2.0",              // 协议版本
  "id": 5,                       // 请求序号
  "method": "eth_estimateGas",   // 模拟执行一笔交易，返回它会消耗多少 gas（免费、不上链）
  "params": [                    // 固定 1 个参数：模拟的交易对象（字段与真交易相同，可不带签名）
    {
      "from": "0x1492bb948655f48d970B0459ADdb6D965545fD60",  // 谁发（影响授权检查等模拟逻辑）
      "to": "0x4ed7c70f96b97c1cb7834d7e3c1f0bdc49029551",    // 目标地址（合约或个人）
      "value": "0xde0b6b3a7640000",                          // 随交易发的原生币 = 1 ETH（wei/hex）
      "data": "0x"                                          // calldata；普通转账就是 "0x"（空）；合约调用放这里
      // 也可加 "gas"、"gasPrice" 限定模拟条件，一般省略
    }
  ]
}
// 响应 result: "0x5208"  —— hex 转 10 进制 = 21000 = 普通转账的标准 gas；合约调用更高
// 用途：真发交易时把这个值填进 gasLimit（没用完退回）；模拟失败会直接报错（如余额不足、未授权）

eth_sendRawTransaction — 发已签名交易（唯一写链入口）

{
  "jsonrpc": "2.0",              // 协议版本
  "id": 6,                       // 请求序号
  "method": "eth_sendRawTransaction",  // 把已签名的交易广播上链（节点看不到明文，只看到签名结果）
  "params": [                    // 固定 1 个参数：
    "0x02f8b4018284b0470e8459682f0082520894..."  // RLP 编码 + 签名后的完整交易 hex（原生层签好才发）
  ]
}
// 签名前交易的明文字段（签名后全部揉进上面那串 hex，不再可读）：
// {
//   "nonce":     "0x7",                // 排队号（getTransactionCount "pending" 拿到的）
//   "gasPrice":  "0x9502f900",         // 每单位 gas 出价（eth_gasPrice 拿到的）
//   "gasLimit":  "0x5208",             // gas 上限（estimateGas 预估，没用完退回）
//   "to":        "0x4ed7...9551",      // 收款地址（合约调用时 = 合约地址）
//   "value":     "0xde0b6b3a7640000",  // 随交易发的原生币 = 1 ETH；不转账时 "0x0"
//   "data":      "0x",                 // calldata；纯转账为空，合约调用放这里
//   "chainId":   11155111              // 网络 ID，烧进签名防重放
// }
// ── 签名后 raw hex 的真实结构 = RLP 列表，按顺序编码 10 个字段：
// [ nonce, gasPrice, gasLimit, to, value, data, chainId, v, r, s ]
//   ├─ 前 7 个就是上面的明文（每项转成最小 hex 编码，空 data 是空串）
//   └─ 后 3 个是签名的产物：
//      r, s —— secp256k1 椭圆曲线签名的两个分量（各 32 字节，合计 65 字节）
//      v    —— 恢复标识 = recoveryId + chainId × 2 + 35（EIP-155）
//              Sepolia 例：0 + 11155111 × 2 + 35 = 22310257 = 0x1546d71（另一个值 22310258）
// 关键点：交易明文里没有 from 字段 —— 节点拿 v/r/s 和交易内容做椭圆曲线反推，
// 从签名中恢复出签发地址。"谁发的"不是声明出来的，是密码学证明出来的，
// 所以私钥不进 JS 也能安全签名：原生层拿到 v/r/s 拼 RLP，全程不需要把私钥交出去。
// 项目里 Trust Wallet Core（AnySigner.sign）做的就是：拼 RLP → keccak256 → 签名 → 编出 raw hex
// 响应 result: "0x8e7a...a1c2"  —— 交易哈希（此时交易刚进 mempool，还没上链）
// 拿这个哈希去 eth_getTransactionReceipt 轮询，直到拿到回执才知道成败

eth_getTransactionReceipt — 查交易回执

{
  "jsonrpc": "2.0",              // 协议版本
  "id": 7,                       // 请求序号
  "method": "eth_getTransactionReceipt",  // 查交易的最终执行结果
  "params": [                    // 固定 1 个参数：
    "0x8e7a1f6c...a1c2"          // sendRawTransaction 返回的交易哈希
  ]
}
// 响应（交易还在 mempool 时 result 为 null —— 项目里轮询直到非 null）
{
  "result": {
    "status": "0x1",             // 0x1 成功 / 0x0 失败（失败不退已耗 gas）
    "transactionHash": "0x8e7a...a1c2",  // 交易哈希（原样）
    "blockNumber": "0x64a3b",    // 打包进的区块号（hex）
    "gasUsed": "0x5208",         // 实际消耗；gasUsed × gasPrice = 真实手续费（未用完的 gasLimit 不计费）
    "logs": []                   // 事件日志数组；合约执行产生的事件（Transfer、Swap 等）都在这里
  }
}

二、代币方法（ERC20）

ERC20 没有独立 RPC，全部通过 eth_call（读）/ eth_sendRawTransaction（写）携带 calldata 实现。calldata = 4 字节函数选择器 + 参数按 32 字节对齐：地址左补 24 个 0，数值左补 0 到 32 字节。

balanceOf(address) — 查代币余额（读）

{
  "jsonrpc": "2.0",              // 协议版本
  "id": 11,                      // 请求序号
  "method": "eth_call",          // 只读调用：模拟执行合约、不花钱、不上链、不用签名
  "params": [                    // 固定 2 个参数：
    {                            // ── 参数1：调用对象（发给谁、执行什么）
      "to": "0xaA8E23Fb1079EA22e0C0e5f5c699a064499F7C25",  // 目标合约地址 = 代币合约（不是钱包地址！）
      "data": "0x70a08231"       // calldata 前段：balanceOf(address) 的 4 字节函数选择器
              + "0000000000000000000000001492bb948655f48d970B0459ADdb6D965545fD60"
                                 // calldata 后段：唯一参数 = 查谁的余额，地址左补 24 个 0 凑满 32 字节
      // "from" / "value" 可选字段一般省略
    },
    "latest"                     // ── 参数2：在哪个区块的状态上执行（latest 最新已确认块）
  ]
}
// 响应 result: "0x0000...5f5e100"  —— 一个 32 字节 word
// hex 转 10 进制 = 100000000；USDT 是 6 位小数 → ÷ 10^6 = 100 USDT（不是 ÷ 10^18）

decimals() — 查精度（读）

{
  "jsonrpc": "2.0",              // 协议版本，固定 2.0
  "id": 12,                      // 请求序号，响应原样带回，用于配对响应和请求
  "method": "eth_call",          // 只读调用：模拟执行合约、不花钱、不上链、不用签名
  "params": [                    // 固定 2 个参数：
    {                            // ── 参数1：调用对象（发给谁、执行什么）
      "to": "0xaA8E...7C25",      // 目标合约地址，这里 = 代币合约（不是钱包地址！）
      "data": "0x313ce567",      // calldata：前 4 字节 = decimals() 的函数选择器
                                 // 无参数函数后面什么都不跟；有参数就按 32 字节对齐接在后面
      // "from": "0x1492..."     // 可选字段：以谁的身份模拟（查 msg.sender 相关逻辑才需要）
      // "value": "0x0"          // 可选字段：模拟时随附的原生币（decimals 用不到）
    },
    "latest"                     // ── 参数2：在哪个区块的状态上执行
                                 // "latest" 最新已确认块 / "pending" 含未打包交易 / "0x64a3b" 指定块号
  ]
}
// 响应 result: "0x6"  —— 一个 32 字节 word，hex 转十进制才是真值：
// parseInt("6", 16) = 6 → USDT/USDC 是 6 位小数；多数代币返回 "0x12" = 18 位

symbol() — 查代币符号（读）

{
  "jsonrpc": "2.0",              // 协议版本
  "id": 13,                      // 请求序号
  "method": "eth_call",          // 只读调用
  "params": [                    // 固定 2 个参数：
    {
      "to": "0xaA8E...7C25",      // 目标合约 = 代币合约地址
      "data": "0x95d89b41"       // calldata：symbol() 的选择器，无参数
    },
    "latest"                     // 执行区块
  ]
}
// 响应是动态类型（string），3 个 word：
// word1: 0x...0020      // 偏移 0x20：数据部分从第 32 字节后开始（动态类型的固定头）
// word2: 0x...0004      // 字符串长度 = 4 个字节
// word3: 0x55534454...  // 内容按 UTF-8 字节："USDT"（55='U' 53='S' 44='D' 54='T'），右侧补 0 凑满 32 字节

allowance(address,address) — 查授权额度（读）

{
  "jsonrpc": "2.0",              // 协议版本
  "id": 14,                      // 请求序号
  "method": "eth_call",          // 只读调用
  "params": [                    // 固定 2 个参数：
    {
      "to": "0xaA8E...7C25",      // 目标合约 = 代币合约地址
      "data": "0xdd62ed3e"       // calldata 前段：allowance(address,address) 的选择器
              + "0000...1492bb...fD60"  // 参数1 = owner（钱的主人）
              + "0000...10ED43...24E5"  // 参数2 = spender（被授权的合约，如 Router）
                                 // 两个地址各左补 24 个 0 凑满 32 字节
    },
    "latest"                     // 执行区块
  ]
}
// 响应 result: "0x0"  —— 0 = 还没授权过，Router 动不了你的代币
// 非 0 = 上次 approve 留下的剩余额度（最小单位整数）

approve(address,uint256) — 授权（写，要签名 + gas）

{
  "jsonrpc": "2.0",              // 协议版本
  "id": 15,                      // 请求序号
  "method": "eth_sendRawTransaction",  // 写操作：发已签名交易（签名前还要过生物识别）
  "params": [                    // 固定 1 个参数：
    "0x..."                     // 原生层签名后的完整交易 hex；明文字段构造如下：
  ]
}
// 交易明文：
// "to":        "0xaA8E...7C25",  // 目标 = 代币合约（不是 Router！approve 是发给代币合约的）
// "value":     "0x0",            // 不带原生币
// "data": "095ea7b3"             // calldata 前段：approve(address,uint256) 的选择器
//        + "0000...10ED43C7...24E5"  // 参数1 = spender（被授权的合约，如 Router）
//        + "0000...05f5e100"     // 参数2 = amount = 100000000 = 100 USDT（6 位小数）
// "nonce"/"gasPrice"/"gasLimit"/"chainId"  // 签名时照常填（getTransactionCount / gasPrice / estimateGas / chainId）
// 效果：spender 之后可以从你地址 transferFrom 最多 100 USDT（额度可累积）
// （签名后 raw hex 的内部结构 [.. v, r, s] 见上面 eth_sendRawTransaction 一节，所有写交易相同）

transfer(address,uint256) — 代币转账（写）

{
  "jsonrpc": "2.0",              // 协议版本
  "id": 16,                      // 请求序号
  "method": "eth_sendRawTransaction",  // 写操作：发已签名交易
  "params": [ "0x..." ]          // 签名后的完整交易 hex；明文字段构造如下：
}
// 交易明文：
// "to":        "0xaA8E...7C25",  // 目标 = 代币合约地址（注意不是收款人地址！收款人在 data 里）
// "value":     "0x0",            // 代币转账不带原生币（原生币转账才用 value）
// "data": "a9059cbb"             // calldata 前段：transfer(address,uint256) 的选择器
//        + "0000...4ed7c70f...9551"  // 参数1 = 收款地址
//        + "0000...05f5e100"     // 参数2 = 金额 = 100000000 = 100 USDT（6 位小数）
// 交易费：gas 由代币转账逻辑消耗（约 6 万 gas），与转账金额大小无关

三、合约调用方法（DeFi）

读走 eth_call，写走 eth_sendRawTransaction。这里列项目用到的 DEX（Uniswap V2 兼容）和 Aave 的典型调用。数组参数比普通参数多一层头：偏移 0x20 + 长度。

Factory.getPair — 查交易对地址（读）

{
  "jsonrpc": "2.0",              // 协议版本
  "id": 21,                      // 请求序号
  "method": "eth_call",          // 只读调用
  "params": [                    // 固定 2 个参数：
    {
      "to": "0xFactory合约地址",  // 目标 = Factory 合约（管所有池子的登记处，不是 Router）
      "data": "0xe6a43905"       // calldata 前段：getPair(address,address) 的选择器
              + "0000...WETH地址"  // 参数1 = tokenA（左补 0 到 32 字节）
              + "0000...USDT地址"  // 参数2 = tokenB
                                 // 传参顺序不影响结果（合约内部会排序）
    },
    "latest"                     // 执行区块
  ]
}
// 响应 result 是一个 word，右取 20 字节才是地址：
// "0x0000...9ed3...4c1a"  → pair 合约地址（池子的门牌号）
// "0x0000...0000"（全 0）  → 没有这个交易对（不是报错！项目里用 BigInt(pair) === 0n 判断）

Pair.getReserves — 查池子储备（读）

{
  "jsonrpc": "2.0",              // 协议版本
  "id": 22,                      // 请求序号
  "method": "eth_call",          // 只读调用
  "params": [                    // 固定 2 个参数：
    {
      "to": "0x9ed3...4c1a",      // 目标 = pair 合约地址（getPair 查出来的门牌号）
      "data": "0x0902f1ac"       // calldata：getReserves() 的选择器，无参数
    },
    "latest"                     // 执行区块
  ]
}
// 响应 3 个 32 字节 word（固定顺序）：
// word1: 0x...0439b0   → reserve0 = 300867216000000（token0 的储备，按 token0 的 decimals 翻译：USDT 6 位 → 300.867216）
// word2: 0x...0e3af2   → reserve1 = 76221000000000000（token1 的储备，ETH 18 位 → 0.076221）
// word3: 0x...8f2a1c   → blockTimestampLast（最近一次交易的时间戳，一般不用）
// 注意：reserve0/reserve1 对应 token0/token1 的地址排序，不是 USDT/ETH 的展示顺序

Router.getAmountsOut — 链上报价（读）

{
  "jsonrpc": "2.0",              // 协议版本
  "id": 23,                      // 请求序号
  "method": "eth_call",          // 只读调用（真实报价含 0.25% 手续费和滑点影响）
  "params": [                    // 固定 2 个参数：
    {
      "to": "0xRouter合约地址",   // 目标 = Router 合约（用户交易的入口）
      "data": "0xd06ca61f"       // calldata 前段：getAmountsOut(uint256,address[]) 的选择器
              + "0000...16345785d8a0000"  // 参数1 = amountIn = 1e17 = 0.1 ETH
              + "0000...0020"     // 参数2头 = 数组偏移 0x20（数据从第 32 字节后开始）
              + "0000...0002"     // 数组长度 = 2
              + "0000...WETH地址" // path[0] = 卖出的代币
              + "0000...USDT地址" // path[1] = 买入的代币
    },
    "latest"                     // 执行区块
  ]
}
// 响应：动态数组 = [偏移, 长度, 元素...]，前两个 word 跳过，后面的对应 path 每个节点：
// word3: 0x...16345785d8a0000    // path[0] 的输出 = 输入原样 1e17
// word4: 0x...17882b80           // path[1] 的输出 = 394800000 = 394.8 USDT（已扣手续费）
// 项目里 decodeWords().slice(2) 就是跳过前两个头 word

Aave.getUserAccountData — 账户健康数据（读）

{
  "jsonrpc": "2.0",              // 协议版本
  "id": 24,                      // 请求序号
  "method": "eth_call",          // 只读调用
  "params": [                    // 固定 2 个参数：
    {
      "to": "0xAavePool合约地址", // 目标 = Aave Pool 合约
      "data": "0xbf25e701"       // calldata 前段：getUserAccountData(address) 的选择器
              + "0000...1492bb...fD60"  // 参数 = 查谁的账户
    },
    "latest"                     // 执行区块
  ]

四、读写参数对比（原生币 / ERC20 / 合约）

三种写操作走的是同一个 RPC eth_sendRawTransaction，唯一区别就是明文里 to / value / data 三个字段的填法。签名外壳（nonce/gasPrice/gasLimit/chainId）完全相同。

字段① 发送原生币② ERC20 transfer / approve③ 合约写方法（swap / supply / 加流动性）
to收款人地址（个人钱包）代币合约地址（不是收款人！）业务合约地址（Router / Aave Pool）
value= 转账金额（1 ETH → 0xde0b6b3a7640000）恒为 "0x0"有原生币参与时 = 原生侧金额（swap 卖出量、加流动性 ETH 侧）；否则 "0x0"
data"0x" 空串（无合约逻辑）selector + 参数：收款人、金额都在这里selector + 参数：最复杂，可能含数组（path）多层头
真正的动作在哪外层 to/value 本身外层只是门牌，动作全在 data部分在 value（原生侧），其余在 data
approve 前置不需要transfer 不需要（approve 自己就是授权）涉及代币侧就需要：先 approve Router/Pool 动你的代币
gas 量级21000（固定）约 5–6 万几十万（swap ~15 万、加流动性 ~30 万）

通用参数（三种写交易完全相同）

字段填什么来源注意
nonce该账号已发交易数（hex）eth_getTransactionCount(addr, "pending")用 "pending" 防 mempool 里未打包交易导致 nonce 撞车；填错交易会被卡住或拒收
gasPrice每单位 gas 出价（wei/hex）eth_gasPrice（可适当上浮 10% 加速打包）实际手续费 = gasUsed × gasPrice，gasLimit 没用完的部分不计费
gasLimitgas 上限（hex）eth_estimateGas（模拟预估值）给少 → 交易 revert 且 gas 照扣；给多 → 只按实际 gasUsed 收费，多余不用白不用
chainId网络 ID（如 Sepolia 11155111）eth_chainId烧进签名防重放：别的网络上这笔交易无效
from不在明文里—（从 v/r/s 签名反推恢复）谁发的不是声明出来的，是密码学证明出来的；原生层签名也因此不需要私钥进 JS
签名v, r, s 追加在 RLP 尾部原生层（Trust Wallet Core AnySigner.sign）JS 层只传地址引用 + 明文参数，签名全程在原生侧完成
